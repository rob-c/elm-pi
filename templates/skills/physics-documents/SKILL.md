# Physics slides, notes and papers

## Before writing anything long

1. **Outline file** in the working directory (`outline.md`): every section or
   slide with its one-line purpose, in order, with the slide/page budget.
2. **Notation file** (`notation.md`): every symbol, its meaning and units, the
   conventions (metric signature, units ħ = c = 1 or SI, Fourier convention,
   normalisations). If the user's course or paper has notation, use theirs.
3. Then write section by section, and check each against both files. For long
   decks, delegate sections to sub-agents and give every one the same outline
   and notation file paths; check the assembled result for symbol drift.

## LaTeX

- Slides: `\documentclass{beamer}`; one idea per frame; no more than one
  derivation step block per frame; `\note{}` for speaker notes.
- Units with `siunitx`: `\SI{80.37}{\giga\electronvolt}`, `\si{\metre\per\second}`;
  never type units by hand in maths mode.
- Equations: `align`/`equation` with `\label` and `\eqref`; define every symbol
  at first use; vectors and operators consistent with the notation file.
- Figures generated by a script in the working directory (see
  `scientific-python`), included as PDF; the script is part of the
  deliverable.
- Build with `latexmk -pdf main.tex` (or `pdflatex` twice) and fix every error
  and undefined reference before reporting; give the page/slide count.

## References

Cite only works you can identify exactly: from the user's files or bibliography,
or read in this session. Never invent a BibTeX entry, DOI, arXiv number, page
or equation number. If a citation is needed and you cannot verify it, leave a
visible `\textbf{[ref needed: ...]}` and list it in the report.

## Content for students

Pitch to the stated audience: say what is assumed knowledge. State physical
assumptions and the regime of validity next to each result; include at least
one limiting-case check (see `derivation-checks`) for each key formula, and
worked examples with numbers and units.
